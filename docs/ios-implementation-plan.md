# MarketPilotDaily iOS 实现方案

> 已被替代：用户已取消 iOS App，当前采用网页管理持仓与自动邮件日报。请以 [网页持仓与每日邮件实现方案](web-email-implementation-plan.md) 为准。本文件仅保留作历史记录，其中本地存储、前台生成和苹果签名要求不再适用于当前方案。

版本：v1.1｜编写日期：2026-09-11｜状态：开发方案，尚未实现

本方案用于指导个人股市分析 App 的设计、开发和验收。最终采用用户已确定的方式：**持仓保存在手机；打开 App 后联网获取信息并生成日报；每天北京时间 08:30 通过本地通知提醒打开 App。无需自建服务器。**

本轮核验了 Apple、数据供应商、模型供应商和开源项目的公开文档；未使用真实 API Key 完成付费接口联调，也未编译 iOS App。下文的技术选型是建议，性能数值是待测试目标，不是已验证结果。

预算更新：用户只愿为 AI API 付费。当前方案不购买行情、新闻搜索、服务器或开发者会员；免费来源失效时显示缺失，不自动升级付费服务。原生 iOS 的免费安装需要可用的 Mac，并接受免费签名周期限制，设备条件尚待确认。预算约束已确定，以下免费数据源组合仍需联调验证。

## 1. 已确定的需求与设计默认值

| 持仓管理 | 添加、编辑、删除当前持仓 | 用户已确定 |

| 基础设施 | 不部署自建服务器、不依赖 APNs 远程推送 | 用户已确定 |

若用户持有港股或美股，应在数据接入阶段纳入首版，并补齐证券代码、币种、汇率和当地交易日历的验收，不需要改为服务器架构。

### 1.1 第一版应交付

- 本地持仓管理、可用现金及投资偏好设置。
- 过去 24 小时新闻与公告摘要，以及最近有效交易时段的行情摘要。
- 基于持仓的风险提示和三个期限的条件性建议。
- 08:30 本地提醒、打开后生成、手动刷新、进度与失败重试。
- 历史日报、生成时的持仓快照、证据来源和数据时间。
- 数据缺失与陈旧状态明确展示；缺乏依据时保留判断。

### 1.2 本轮不实现

自动下单、券商账户连接、完整交易流水和已实现收益核算、全天实时监控、后台定时研究、多用户服务、订阅收费、跨设备自动同步、模型训练与策略回测。需要这些功能时单独设计，不能通过增加几个提示词宣称已经支持。

## 2. 用户体验与页面

采用四个底部入口：**日报、持仓、历史、设置**。日报优先显示结论和证据，技术参数放在设置或诊断信息中。

### 2.1 首次使用

1. 说明工作方式：打开后分析，联网调用服务，可能产生接口费用。
2. 引导配置模型个人凭证，检查免费数据源；只有不产生费用的服务确需注册时才配置其个人凭证。
3. 录入持仓和可用现金；选择投资期限，填写自己能接受的回撤或暂时跳过。
4. 说明发送给模型的数据类别，由用户启用在线分析。
5. 用户启用每日提醒后，再请求通知权限；拒绝通知不影响使用。
6. 用户点击一次“生成首份日报”。成功后启用“每天首次打开自动分析”。

不提供开发者共享密钥；没有凭证时可以编辑持仓和阅读已保存报告，不能生成假装来自真实市场的演示分析。

### 2.2 日报页

展示顺序：

1. 报告日期、生成时间、新闻窗口、行情截至日期、持仓是否匹配。
2. 今天最重要的三件事，每件事说明与持仓的关联。
3. 国内外指数和市场变化，明确收盘价、盘中快照或延迟行情。
4. 资金与交易活跃度，附来源、单位和统计口径。
5. 账户风险与每只持仓的变化。
6. 今日、短期、长期建议；未变化的长期判断可以折叠。
7. 未来事件日历、来源列表和数据缺失项。

主要按钮：生成日报、刷新分析、取消、重试、查看来源。生成过程显示实际阶段，不伪造百分比；数据获取阶段可显示已完成的请求数量。

空持仓时允许生成市场日报，账户和个股建议显示“添加持仓后启用”。当日休市时仍可生成报告，“今日操作”改为“下一交易日准备”。

### 2.3 持仓页

字段：证券、数量、平均成本、投资期限、买入理由；证券名称、市场、类型和币种由已验证的证券资料补全。

交互规则：

- 搜索或输入代码后必须选择明确的证券，不能只按模糊名称保存。
- 同一市场和类型的同一证券只保留一条当前持仓。再次添加时引导编辑，不重复累计。
- 数量必须为正数；未知成本允许留空，相关盈亏显示“未填写成本”。成本为零与未知必须区分。
- “修改持仓”是修改当前数量和成本，不是假设发生了一笔交易。
- “加仓／减仓”如作为快捷入口，也必须展示修改后的总数量与平均成本供确认；不能暗中推算交易盈亏。
- 删除持仓不自动修改现金，修改数量不自动扣减现金。第一版没有交易流水，现金由用户单独维护。
- 删除提供撤销；历史日报仍引用原有快照。设置页说明清空全部本地数据会同时清除这些历史快照。
- 展示“你填写的持仓截至时间”。长期未更新时提醒核对，不能称为券商实时持仓。

### 2.4 历史与设置

历史按日期列出，同一天手动刷新产生多个版本。默认展示最新成功版本，允许查看旧版本及当时的持仓。

设置包含：服务商凭证、连接测试、通知开关和时间、投资偏好、可用现金、自动分析开关、清理缓存、清空本地数据。凭证输入后脱敏显示；连接诊断不回显密钥。

## 3. 打开后分析与报告版本

### 3.1 自动触发规则

| 打开 App 时的状态 | 行为 |
| --- | --- |
| 首次使用且设置未完成 | 展示引导，不发起付费分析 |
| 今天没有成功日报，设置已完成且自动分析开启 | 前台启动一次分析 |
| 今天已有日报且持仓、偏好未变化 | 直接展示，不自动重复调用模型 |
| 今天已有日报，但持仓或偏好变化 | 展示旧日报与“资料已变更”提示，用户点击重新分析 |
| 同一分析正在运行 | 回到进度界面，不创建第二个任务 |
| 自动分析失败或被中断 | 显示原因和重试按钮；本日不因反复切回 App 而自动重试 |
| 无网络 | 读取历史和持仓，提示联网后生成 |

App 从后台回到前台也适用同一套去重规则。跨过北京时间零点后进入新的报告日期；提醒通知仅导航到日报页，由同一规则决定是否开始生成。

### 3.2 快照与缓存键

每次运行记录：`runID`、`reportDate`、`startedAt`、`cutoffAt`、`portfolioRevision`、`profileRevision`、`promptVersion`、`schemaVersion`、`modelID`、`providerConfigRevision`。

其中 `cutoffAt` 固定为本次开始分析的时间，新闻窗口为 `[cutoffAt - 24h, cutoffAt)`。报告完成时显示实际 `generatedAt`，不能把生成完成时间当作新闻截止时间。

同一天不同 `runID` 是不同版本。运行前按相关证券稳定排序，使用规范化十进制字符串保存快照；采用持仓和偏好版本判断缓存失效。`providerConfigRevision` 只反映非敏感配置变化，不包含密钥。

持仓在分析过程中被修改时，本次继续使用启动时的不可变快照；完成后标记“基于修改前持仓”，由用户决定是否重算。修改、删除当前持仓不能级联修改历史报告。

缓存采用以下初始规则，供应商声明更严格时以供应商为准：

| 内容 | 初始复用规则 | 手动刷新时 |
| --- | --- | --- |
| 证券身份和名称 | 最多 7 天，校验失败立即失效 | 必要时重新解析 |
| 盘中报价 | 最多 60 秒；读取时仍检查供应商时间 | 重新获取 |
| 完整历史日 K | 已完成交易日按增量更新；复权因子变化时重取受影响区间 | 检查最新交易日及更正 |
| 新闻搜索结果 | 相同查询最多复用 10 分钟，仍重新按本次截止时间过滤 | 重新搜索 |
| 财务及资金数据 | 按数据所属期和发布日期保存；每个新报告日检查是否更新 | 重新检查来源更新 |
| 已生成日报 | 当日优先读取；持仓／偏好变化时标记失效 | 新建版本，不覆盖旧报告 |

缓存过期不意味着旧证据自动变成错误，但必须以原时间标记，不能用缓存时间冒充最新数据。数据源不可用时，旧数据只作为背景或明确标注的估值参考。

### 3.3 中断与恢复

状态机：`idle → preparing → fetching → calculating → analyzing → validating → saving → completed`。执行阶段可转为 `failed`、`cancelled` 或 `interrupted`。

- 前台以 Swift 并发任务运行；进入后台时不依赖任务继续完成。
- 保存已完成阶段的缓存和运行状态，取消尚未结束的网络请求；系统给出的短暂后台时间只用于必要的收尾。
- 再次打开时，未结束的旧运行标记为 `interrupted`。第一版由用户点击重试，以新的截止时间启动，不承诺从模型输出中间继续。
- 模型请求可能已到达服务商，取消客户端请求不能保证不计费；不因网络结果不明而自动重发模型请求。
- 只有校验完成并原子保存后才标记成功。失败不覆盖已有日报。

Apple 后台执行由系统调度，不能作为每天定时计算的保证；这也是采用前台分析的原因。[Apple 后台策略](https://developer.apple.com/documentation/BackgroundTasks/choosing-background-strategies-for-your-app)

## 4. iOS 技术架构

| 层 | 技术建议 | 职责 |
| --- | --- | --- |
| 界面 | SwiftUI、NavigationStack、系统表单与列表 | 四个页面、进度、来源详情 |
| 状态与编排 | Observable 状态、actor、async/await | 前台任务、取消、去重和快照 |
| 持久化 | SwiftData，关闭 CloudKit 自动同步 | 持仓、偏好、日报与运行元数据 |
| 结构化载荷 | Codable JSON，存入日报快照字段或受保护的本地文件 | 证据包和报告版本 |
| HTTP | URLSession | HTTPS 直连供应商，限流和错误映射 |
| 凭证 | Keychain Services | 个人 API Key 和 Token |
| 本地通知 | UserNotifications | 每天提醒与点击跳转 |
| 基础计算 | Swift Decimal；统计运算按需用 Double | 市值、盈亏、仓位与指标 |
| 测试 | XCTest、URLProtocol 测试替身、XCUITest | 计算、接口解析、用户流程 |

调用方向：

```text
SwiftUI 页面
   ├── 本地持仓 / 偏好 / 历史日报
   └── AnalysisCoordinator
         ├── 行情与财务数据服务（HTTPS）
         ├── 搜索与事件资料服务（HTTPS）
         ├── 本地校验、计算、证据整理
         ├── 模型服务（HTTPS）
         └── 报告校验 → 保存 → 显示

iOS 本地通知 → 打开日报页 → 根据状态决定是否分析
```

不新增 FastAPI 服务、云数据库、Cron、Redis 或远程推送服务。数据供应商和模型供应商本身仍是远程服务，“无自建服务器”不等于离线运行。

参考：[SwiftData](https://developer.apple.com/documentation/swiftdata)、[Keychain Services](https://developer.apple.com/documentation/security/keychain-services)。

## 5. 数据接入路线与必须验证的条件

### 5.1 建议供应商组合

以 **TickFlow 免费日线 + 官方公开公告／RSS + 手机本地计算 + DeepSeek 模型**作为预算内首轮联调候选。Tushare 付费专题数据、博查付费搜索和付费行情不再是当前方案依赖。只实现本项目实际用到的少量接口，不做通用供应商平台；资料覆盖不足时明确展示受限状态。

| 用途 | 首选候选 | 调用方式／依据 | 联调必须确认 |
| --- | --- | --- | --- |
| 证券资料、历史日 K | TickFlow 无需注册的免费服务 | `https://free-api.tickflow.org`，仅采用已验证的免费端点 | 标的覆盖、价格调整方式、时间戳单位、收盘后更新时间 |
| 全球主要指数 | 免费服务内实际支持的指数；官方公开指数资料作为补充候选 | 当前未证明所有目标指数均可免费自动取得 | 每个指数分别确认，ETF 不能冒充指数，缺失不补数 |
| 资金与财务 | 官方公开统计、公司定期报告 | 只接入无需付费且允许读取的资料 | 自动读取方式、统计单位、发布日期；暂无全覆盖保证 |
| 国内新闻和公告 | 交易所、巨潮、公司投资者关系及政策发布页 | 逐站核验允许读取的公开页面或订阅源 | 不假定所有网站有 RSS 或公开 API；处理时效、更正和访问失败 |
| 海外政策消息 | 官方 RSS，例如美联储新闻与政策订阅 | 直接读取 RSS，按发布时间和持仓相关性筛选 | 来源范围、保留条数、时间窗口；不等同全网财经新闻 |
| 分析生成 | DeepSeek | 官方 `POST https://api.deepseek.com/chat/completions` | 当前模型可用性、JSON 输出、响应预算、真机访问 |

TickFlow 的公开文档提供免费历史日 K 服务和带凭证的完整服务；不能把免费日 K 描述成实时行情，其免费服务说明与套餐页面也应在联调时核对，以实际账户权限为准。[开始之前](https://docs.tickflow.org/zh-Hans/quickstart)、[报价接口](https://docs.tickflow.org/zh-hans/api-reference/实时行情/查询实时行情)、[接口目录](https://docs.tickflow.org/llms.txt)

公开网页可免费阅读，不意味着存在稳定、可免费集成的 API。M0 必须验证 HTTPS、访问方式、内容解析、发布时间与使用条件；无法接入的页面只保留来源入口，不能算作自动采集已完成。[巨潮公告入口](https://www.cninfo.com.cn/new/commonUrl/pageOfSearch?url=disclosure/list/search)

前稿的 Tushare 国际指数、资金和财务接口存在积分或独立权限要求，不在本次预算内承诺接入。其文档可以用于核对指标定义，不能把文档示例当作实际取得的数据。[权限说明](https://tushare.pro/document/1?doc_id=290)

新闻改为固定来源采集与本地筛选，不依赖付费搜索，也不依赖试用赠送额度。美联储提供官方 RSS；国内公告源需分别验证，不能据此承诺完整覆盖过去 24 小时国内外消息。[美联储 RSS](https://www.federalreserve.gov/feeds/feeds.htm)

普通模型推理 API 不自动等于联网搜索服务。先取得实际资料再交给模型；如某模型另提供收费搜索工具，本方案默认不启用，避免在推理费用外产生隐藏检索费用。

DeepSeek 的模型名称会变动；接入时从当前官方文档选择一个可用模型，个人高级设置保留模型 ID，避免沿用失效名称。本轮不订购模型服务。[首次调用](https://api-docs.deepseek.com/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)

### 5.2 必需信息与降级行为

| 数据 | 正常用途 | 缺失时的行为 |
| --- | --- | --- |
| 已确认证券身份 | 正确关联持仓 | 身份不明的标的不进入个股建议 |
| 持仓最新有效价格、日期 | 估值和仓位 | 显示缺失；不能据不完整总值给加减仓数量 |
| 国内与海外主要指数 | 市场环境 | 按区域标注缺失，其他区域可继续 |
| 带来源及时间的新闻 | 最近 24 小时事实摘要 | 无可靠时间的结果只作背景资料 |
| 资金流向或融资变化 | 资金章节 | 写明缺失，不用成交额替代净流入 |
| 已公布财务资料 | 长期判断 | 提供待核查项，不生成新的强长期买卖结论 |
| 未来事件与来源 | 事件日历 | 写“未检索到已验证事件”，不写“未来无风险” |
| 可用现金、风险偏好 | 账户约束 | 保留风险解释，暂停具体目标仓位和交易数量建议 |

受限报告不是数据齐全的正式验收替代品。若缺少国际行情、资金或持仓财务资料，应在交付清单逐项记录，不能宣布完整需求已经完成。

### 5.3 获取范围与请求预算

- 国内基础指数先配置上证、深证成指、创业板、沪深 300；海外先配置恒生、恒生科技、标普 500、纳斯达克综合、道琼斯。供应商代码逐一映射，未映射时不能猜代码。
- 全市场涨跌家数仅在取得完整且同口径的标的集合后计算；只拿到持仓样本时不得写成全市场统计。
- 对持仓证券拉取最近约 120 个完整交易日数据，用于基础趋势对照；盘中未结束的日 K 不混入完整日线统计。
- 固定来源按国内宏观、海外市场、未来事件和持仓公告分组。手机从允许访问的源获取资料，再按证券、行业、发布时间过滤；不假设存在免费的全网搜索能力。
- 同一事件去重，优先保留原始发布者和更正版本；每条来源标记是原文、官方短讯、新闻报道还是搜索摘要。
- 原型以 10 只持仓为性能样本；先设最多 20 次资讯来源请求、最多 40 条入模证据，超过预算的部分列明未覆盖，可手动补查，不能静默截断。
- 第一版默认一次模型请求形成整份报告，避免每只股票多轮辩论。上下文过大时先确定性裁剪重复资料，保持每只持仓都有覆盖状态。

## 6. 时间、行情与资金口径

### 6.1 三种时间必须分开

1. `publishedAt`：消息原始发布时间，用于判断是否属于过去 24 小时。
2. `eventAt`：事件发生时间或计划时间，用于区分过去事件和未来日历。
3. `fetchedAt`：本机获取时间，用于判断缓存新鲜度；不能代替消息发布时间。

额外保留 `sourceUpdatedAt` 与发布时间可信度。只有日期没有时刻时，不能假装有精确的 24 小时归属；放入“时间待确认”并与严格窗口分开。

周末、节假日、夏令时按各市场交易日历处理。财经事件按其原始时区解析后展示北京时间。缺乏交易日历时只能写“截至供应商最近返回的交易日，状态未验证”。

报告记录每个市场的 `premarket / intraday / postmarket / nonTrading / unknown` 阶段。盘中打开却只有昨日收盘数据时，仍明确标为昨日行情；收盘后生成时，把该市场的“今日操作”内容改为下一交易日计划。不同市场可以同时处于不同阶段。

App 数日未打开时，主报告仍覆盖本次过去 24 小时；可另列“上次查看后重要补充”，从上次成功报告截止时间起检索并明确独立窗口，不冒充完整的离线期间监控。

### 6.2 行情与估值

- 用不复权的有效成交价或收盘价计算当前市值；用一致调整口径的历史序列计算趋势。
- 报价必须包含币种、市场、时间和交易阶段。没有实时权限时标为“最近收盘估值”，不自动升级成实时价。
- 长期停牌标的即使最近成交价很旧也可保留估值参考，但需标记停牌与估值日期，避免作为可立即成交价格。
- 除权、拆股、分红等事件可能让手工数量或成本失真。提醒用户核对，不在没有流水时自动改写持仓。
- 海外指数成交额缺失不补零，汇率缺失不强行汇总多币种账户。

### 6.3 资金章节

优先展示可核验的成交活跃度、融资余额变化和授权资金指标，每项记录提供者、统计方法、单位和所属日期。不同来源的同名“主力资金”不拼成一条时间序列。

Tushare 的 `moneyflow` 按订单规模及主动买卖口径统计，不能据此确认机构身份或保证未来涨跌。[资金流向定义](https://tushare.pro/document/2?doc_id=170)

沪股通披露机制调整后，不能沿用旧教程把每日成交总额写成北向净流入。若使用估算，必须单列“第三方估算”，说明方法和限制。[上交所披露通知](https://www.sse.com.cn/lawandrules/sselawsrules2025/global/hkexsc/c/c_20250613_10781806.shtml)

## 7. 本地数据模型

金额与数量采用 Decimal 或可无损还原的十进制字符串；时间持久化为 UTC，同时记录原始时区。以下为模型契约，具体 SwiftData 属性在实现时按迁移约束落地。

| 模型 | 主要字段 | 约束 |
| --- | --- | --- |
| `Instrument` | id、market、exchange、code、name、assetType、currency、providerSymbols、industry、metadataAsOf | 身份由市场／交易所／类型／代码确定，不以名称为主键 |
| `Position` | id、instrumentID、quantity、averageCost?、horizon、thesis?、updatedAt | 当前证券唯一；成本缺失合法 |
| `PortfolioState` | revision、cashBalances、cashAsOf、updatedAt | 所有持仓或现金编辑在同一事务内递增版本 |
| `InvestorProfile` | revision、investmentHorizon、drawdownTolerance?、singlePositionLimit?、sectorLimit?、cashNeedDate? | 空值表示未知；不把缺省值当用户认可的风险预算 |
| `EvidenceItem` | id、kind、title、url?、publisher、publishedAt?、eventAt?、fetchedAt、excerpt、relatedInstrumentIDs、quality、contentHash | API 行情通过来源记录及本地快照追溯；新闻保存原始链接 |
| `MarketSnapshot` | id、cutoffAt、quotes、bars、fundFlows、financials、calendarStatus、coverage、evidenceIDs | 每项数据保留日期、单位、来源与缺失原因 |
| `AnalysisRun` | id、state、stage、startedAt、cutoffAt、portfolioRevision、profileRevision、failureCode? | 不保存密钥、原始鉴权头或模型内部推理 |
| `DailyReport` | id、reportDate、generatedAt、runID、inputSnapshot、resultJSON、schemaVersion、promptVersion、modelID、quality | 成功报告不可原地覆盖，手动刷新新增版本 |
| `AppSettings` | reminderEnabled、reminderTime、timeZone、autoAnalyze、lastAutoAttemptDate、providerConfig | 非敏感设置；密钥只存 Keychain |

`DailyReport.inputSnapshot` 保存分析时的持仓、偏好、市场数据与实际入模证据副本，不能只关联可被用户修改或清理的缓存。缓存可删；用户保留的日报仍需可解释。

### 7.1 第一版可计算的指标

```text
持仓市值 = 数量 × 有效不复权价格
未实现盈亏 = 数量 × (有效价格 − 用户填写的平均成本)
未实现盈亏率 = 未实现盈亏 ÷ (数量 × 平均成本)   // 成本总额必须 > 0
已录入投资资产 = 同币种持仓市值合计 + 该币种现金
持仓权重 = 持仓市值 ÷ 已录入投资资产             // 分母必须 > 0 且估值完整
行业集中度 = 同行业持仓市值合计 ÷ 已录入投资资产
```

明确“已录入资产”的范围，不称为用户全部财富。缺失价格、行业或现金的覆盖率必须可见；未知行业列为“未分类”。ETF 不直接等同某个行业，第一版无穿透数据时显示“未穿透”。

没有完整流水时，不计算已实现收益、账户真实日收益率、年化收益或组合最大回撤。账户历史市值变化可能来自用户改仓和现金变动，不能自动当成投资表现。

如纳入港美股，按币种先分组展示。只有全部相关汇率具有来源、时间和一致换算方向时才增加人民币总值，否则禁用跨币种仓位建议。

## 8. AI 分析流程与输出契约

### 8.1 分析步骤

1. 冻结持仓与偏好；确定分析截止时间和市场范围。
2. 并行获取互相独立的行情、资讯与财务资料，按供应商限流。
3. 校验证券身份、单位、时间和覆盖范围，去重并筛选证据。
4. 本地计算指标，生成每只持仓和整个账户的数据覆盖表。
5. 把结构化指标、精选证据及个人偏好发给模型，生成固定 JSON。
6. 本地解析、核对引用和建议一致性；不合法时按规则降级或要求重试。
7. 保存报告与输入快照，使用原生组件展示。

第一版不让模型自行调用任意工具、访问任意地址或执行代码。网页正文是待分析数据，其中的指令不能改变系统规则。无需多智能体、向量数据库或训练专用模型。

### 8.2 发送给模型的内容

默认发送证券身份、持仓权重、持有期限、用户填写的投资理由和风险约束，以及计算后的市场指标与证据。无需发送姓名、账号、设备标识、券商凭证、绝对账户金额和原始持仓数量。

本地仍用真实数量、现金做约束检查。第一版输出方向和条件，不要求模型给出精确下单股数。若未来要发送更多持仓字段，应在设置中说明新增字段及目的。

### 8.3 结果结构

```text
ReportResult
  summary[]                 // 最重要的变化，含 evidenceIDs
  marketOverview[]          // 国内外分区，行情值引用 metricID
  capitalFlowSummary[]      // 指标引用、解释与统计限制
  portfolioRisks[]           // 相关持仓、风险原因、证据
  positionAdvice[]
    instrumentID
    today / shortTerm / longTerm
      action                // observe | hold | consider_reduce | consider_add | insufficient_data
      rationale[]           // 结论与 evidenceIDs
      counterEvidence[]
      triggerConditions[]
      invalidationConditions[]
      reviewAtOrEvent
      evidenceStrength      // sufficient | limited | insufficient，非上涨概率
  upcomingEvents[]          // 已确认安排 / 市场预期 / 情景假设
  limitations[]
```

报告元数据、价格、盈亏等事实值由客户端填写。AI 引用 `metricID` 和 `evidenceID`，不能自行提供页面上的正式行情数字或创建来源 URL。叙述中出现的具体金额、日期和价格仍需与证据核对；结构校验不能代替语义核验。

### 8.4 建议规则

- 今日建议是当前已知信息下的条件计划；盘前不能声称今日突破已发生。
- 短期默认 1–4 周，长期默认 6–24 个月，并结合用户的实际持有计划。
- 长期建议以财务和投资理由变化为依据，不能只根据一天涨跌推翻长期持仓。
- 提供加仓倾向前，必须有完整估值、可用现金和用户确认的风险约束；没有这些信息时保留为观察条件。
- 任何买卖方向都要有支持证据、反对证据或不确定性、触发和失效条件；信息不足不能变成默认看多。
- 各持仓长期／短期建议出现冲突时，明确适用期限与原因；无法解释时降级为观察。
- 传闻不得作为唯一交易依据；未来事件的时间与结果必须分别表达。
- 不生成确定收益承诺，也不把模型信心写成经过统计验证的上涨概率。

### 8.5 输出校验

必查：JSON 类型、枚举、证券集合、引用存在性、未来事件时间、缺失数据对应的建议级别、加仓约束、重复或相互矛盾的建议。

格式错误允许至多一次带错误列表的修复调用，记录额外调用；鉴权失败、额度不足或响应是否完成不明时不自动修复。二次仍失败则保留事实摘要，隐藏未经校验的 AI 建议，显示重试入口。

## 9. 服务接口和错误处理

在业务层定义四个小接口，供应商响应映射到本地统一类型。它们是 App 内部接口，不是自建 HTTP 服务。

```swift
protocol MarketDataProvider {
    func resolveInstrument(query: String) async throws -> [InstrumentDTO]
    func fetchMarketSnapshot(request: MarketRequest) async throws -> MarketSnapshotDTO
}

protocol ResearchDataProvider {
    func fetchResearch(request: ResearchRequest) async throws -> ResearchBundle
}

protocol NewsProvider {
    func search(request: NewsSearchRequest) async throws -> [EvidenceDTO]
}

protocol AnalysisProvider {
    func analyze(input: AnalysisInput) async throws -> ReportResult
}
```

接口名称仅为设计示意；不提前创建动态插件系统、多层抽象工厂或通用工作流引擎。

网络规则：

- 普通数据请求初始超时 20 秒；模型请求初始超时 120 秒；总流程目标上限 180 秒。这些是可根据真机结果调整的工程初值。
- 普通幂等数据请求仅对短暂网络错误、429 和适当的 5xx 有限重试；尊重 `Retry-After`，最多两次，总时限仍生效。
- 同一供应商初始最多两路并发；跨供应商最多四路。实际额度更低时按额度降低。
- 401／403／额度不足不盲目重试，提示对应服务需要修正凭证或权限。
- 取消任务应传播到 URLSession 和子任务；模型调用不在结果不明时自动重复。
- 拒绝传输安全降级；跨域重定向不转发鉴权信息。普通网络日志仅保存服务名、状态码、耗时和请求 ID。

## 10. 本地提醒

使用 `UNUserNotificationCenter` 和重复的 `UNCalendarNotificationTrigger`。提醒使用一个稳定 ID，例如 `daily-report-reminder`，修改时间时替换原请求，关闭时删除该请求。

默认时区固定 `Asia/Shanghai`；在 DateComponents 中明确日历、时区、小时和分钟。设备时区变更、系统时间变化或重新打开设置时核对下一次触发时间，避免旅行后误变成所在地 08:30。

文案：标题“查看今日股市分析”；正文“打开 App，结合你的最新持仓生成日报”。不写“日报已生成”，不在通知中显示股票数量、成本或账户金额。

点击通知进入日报页。设置中提示通知关闭、专注模式等可能影响可见提醒；通知权限拒绝时不反复弹系统请求。需在真机验证锁屏、App 未运行、修改时区与重复注册。

本地通知由系统在已安排的触发条件下处理，不需要部署推送服务器。[Apple 本地通知说明](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)

## 11. 本地保存、隐私与费用

- 凭证存 Keychain，建议使用仅本机、解锁时可访问的策略；不写入 UserDefaults、数据库、Git 或导出的诊断信息。
- 持仓和日报使用系统文件保护；“本地保存”表示不做应用自建云同步，不自动承诺系统备份也完全不含数据。备份策略在上线前测试并明确说明。
- 模型、搜索、行情服务各自仍能收到请求。首次启用在线分析时说明：搜索会涉及股票名称／代码，模型会收到最小化后的持仓与风险信息。
- 不接入广告、第三方行为分析或远程日志。故障定位优先使用本地脱敏日志。
- “清空本地数据”清除持仓、偏好、日报快照、缓存和运行记录；同时取消提醒。凭证是否一并清除在确认界面明确列出，默认一起清除。
- 请求预算和模型响应中的用量可以本地记录。账单以供应商为准；无有效费率时显示调用次数和 Token 数，不伪造人民币费用。

服务支出仅允许 AI 模型 API。行情、财务资料和新闻只使用已验证的免费来源，不购买搜索额度，不依赖需要续费的试用方案。免费来源变化时停止对应数据项并提示，不能自动切换付费来源。

原生 iOS 安装也有约束：若已有可用 Mac，可用免费 Apple 账号通过 Xcode 安装到自己的 iPhone，但免费 provisioning profile 在签发 7 天后到期，需要重新构建安装。不能把这描述为永久免维护安装；本方案不购买开发者会员。[Apple 个人开发账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account)

若没有可用 Mac，先讨论入口调整，不能把新购硬件或租用 Mac 的费用隐藏在“免费”中。可用 iPhone 快捷指令验证采集与分析流程，但它不等同本方案的完整独立 App；是否接受此替代尚未决定。[快捷指令调用 API](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios)

```text
单次模型费用估计 = 输入用量 × 对应输入单价 + 输出用量 × 对应输出单价
月度服务费用估计 = 各次 AI 模型实际调用费用合计
```

默认每日自动分析至多尝试一次；手动刷新提示会重新获取资料并可能产生调用费用。已有当天日报时不因进入页面重复付费生成。

## 14. 分阶段实施与完成条件

### M0：验证直连接口和运行环境

工作：核对真实持仓市场、设备系统、Mac／Xcode 环境；在不记录密钥的条件下测试所需接口。创建一份字段覆盖表，记录每项接口的权限、时间、单位和样例。

完成条件：

- 至少一只目标市场证券的身份、最近报价、历史日线可在 iOS URLSession 下读取。
- 国内和海外指数、资金、财务、搜索的成功或缺失状态逐项明确。
- 模型能返回可解析结构；验证一次短输入和一次接近正式报告规模的输入。
- 证明客户端个人凭证模式可用，费用和授权范围明确；未获凭证时只能记“未验证”。

数据源验证可以与本地持仓界面开发并行推进，但没有验证不能宣称完整日报已可用。

### M1：本地 App 骨架与持仓

工作：建立 Xcode 项目、四个入口、SwiftData 模型、持仓和现金编辑、Keychain 配置页。

完成条件：重启后数据保留；证券身份不会混淆；数量和成本边界处理正确；修改产生版本变化；本地数据可清除。先用显式测试数据验证界面，测试模式不得伪装成真实日报。

### M2：市场资料与事实摘要

工作：实现已验证的数据适配器、时间窗口、缓存、去重和确定性指标；形成无需 AI 的事实页面。

完成条件：随机抽查证券、日期和单位与来源一致；休市日期处理正确；缺失数据未填零；搜索摘要与原文可区分；全球与资金章节覆盖状态可见。

### M3：持仓分析和报告版本

工作：实现证据包、单次模型分析、固定结构解析、建议规则、历史快照和手动刷新。

完成条件：三个期限建议都有适用条件与证据；不支持的判断会降级；途中改仓不污染快照；失败不覆盖旧日报；同日再次打开不重复调用。

### M4：提醒、中断恢复和真机验收

工作：本地通知、每日自动触发、前后台切换、超时、取消和网络失败场景。

完成条件：通知不会声称报告提前生成；重复配置不产生多条提醒；中断可重试；关闭网络能读历史；测试结果记录真实耗时和费用。

### M5：个人试用

工作：使用真实但由用户维护的持仓连续试用，核对日报是否易读、来源是否可靠、数据费用是否可接受。

完成条件：至少覆盖普通交易日、休市日、手动改仓和一次服务失败。修复误导性数字、错误引用和重复计费触发后，再决定是否扩大市场范围或公开发布。试用成功不等于证明建议有长期盈利能力。

## 15. 验收清单

| 编号 | 场景 | 必须达到的结果 |
| --- | --- | --- |
| A01 | 添加、编辑、删除持仓后重启 | 当前持仓正确保存；删除可撤销；历史快照不变 |
| A02 | 同名证券、相似代码、ETF 与股票 | 精确匹配市场和类型，不串数据 |
| A03 | 数量负数、未知成本、零成本、现金未填 | 非法数量拒绝；未知与零区分；不除零、不伪造仓位 |
| A04 | 计算样例：数量 100、成本 10、价格 12、现金 800 | 市值 1200、未实现盈亏 200、盈亏率 20%、已录入资产 2000、权重 60% |
| A05 | 有持仓价格缺失或币种无法换算 | 覆盖率可见；总资产或精确仓位标为不可用 |
| A06 | 当天二次打开、前后台来回切换 | 不重复自动分析，不并发生成同一任务 |
| A07 | 生成时修改持仓 | 本次快照一致；完成后提示与当前持仓不同 |
| A08 | 同日手动刷新 | 新增报告版本，旧版本与证据仍可阅读 |
| A09 | 24 小时边界、无发布时间、转载旧消息 | 窗口准确；未知时间单列；转载不自动视为新事件 |
| A10 | 周末、跨时区、美股夏令时、停牌 | 数据日期正确，不把旧收盘写成今日实时行情 |
| A11 | 缺资金或财务权限 | 明确缺失；不补数字；长期或资金判断相应降级 |
| A12 | JSON 损坏、虚构来源 ID、错误证券 | 被校验拦截；有限修复后仍错则隐藏建议 |
| A13 | 缺现金或风险约束却出现加仓建议 | 降为观察条件，不能显示可执行的加仓数量 |
| A14 | 新闻正文夹带指令 | 不执行指令、不泄露密钥、不改变输出规则 |
| A15 | 无网、超时、401、403、429、5xx | 错误可理解；重试有上限；已存日报保持可用 |
| A16 | 生成中锁屏、切后台、系统终止或用户取消 | 状态可恢复识别，不把部分结果当完整报告 |
| A17 | 通知拒绝、开启、改时间、重复设置、改时区 | App 可继续用；待触发提醒唯一；北京时间语义保持一致 |
| A18 | 日志、缓存、清空数据 | 无明文密钥日志；清空操作覆盖日报内持仓快照 |
| A19 | 空持仓与大于性能样本的持仓 | 空持仓有市场日报；超预算明确未覆盖，不静默漏股票 |
| A20 | 真机性能和费用 | 保存设备、网络、证券数、耗时和用量；目标为 10 只持仓大部分运行 30–120 秒，超时按规则处理 |

自动测试优先覆盖计算、日期、快照、解析、去重和建议拦截；接口测试使用脱敏固定响应。真实凭证的联网测试单独执行，不放进默认 CI，不将不可复现的市场涨跌当测试断言。

语义抽查包括：引用是否真正支持结论、事件是否与持仓有实际关联、长期判断是否被短期噪声误导。不能只通过 JSON 格式正确就验收 AI 分析质量。

## 16. 开发前需补充的信息

这些信息不影响本方案文档完成，但会影响实际开发与真机联调：

1. iPhone 型号和 iOS 版本；是否具备可使用的 Mac／Xcode。当前工作区在 Windows，可编写文档与源码，iOS 编译、签名和真机测试需在支持的 Mac 环境完成。[Xcode 系统要求](https://developer.apple.com/xcode/system-requirements)
2. 实际持仓市场、资产类型和大致数量；是否需要港股／美股进入首版。
3. 已有的模型账户及可接受的 AI 调用预算；其他数据源只允许免费方案。凭证在 App 或本机安全配置中录入，不要求粘贴进文档。
4. 是仅个人使用，还是准备公开上架。公开提供投资相关功能时再核对发行地区、数据授权和 Apple 的适用审核要求。[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)

开发起点为 M0 和 M1。完整交付以验收清单及真实接口覆盖记录为准，不能以页面能打开或模型能输出文字代替完成标准。
