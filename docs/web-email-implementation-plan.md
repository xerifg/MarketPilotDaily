# MarketPilotDaily 网页持仓与每日邮件实现方案

版本：v2.0｜日期：2026-09-11｜状态：当前开发方案，尚未实现、部署或启用发送

## 1. 当前决定

用户已取消原生 iOS App，改为：**通过网页管理个人股票持仓，每天北京时间 08:30 左右收到基于最新持仓的分析邮件。只有 AI API 允许付费。**

“个人仓库”按上下文理解为股票持仓。网页需要支持追加、修改和删除持仓，手机与电脑浏览器均可使用。邮件渠道和使用 **163 邮箱发送**均已由用户确认，具体发件地址、收件地址及授权信息尚待配置。

本方案替代 `ios-implementation-plan.md` 的技术路线。取消 iOS 客户端、Mac／Xcode、苹果签名、本地通知和打开后才分析的限制。持仓由手机本地存储改为受访问控制保护的云端存储，定时任务因此可以在用户设备关闭时工作。

需要后台运行能力，但不租用独立服务器；优先使用免费托管服务的额度。免费额度、账号可用性、国内访问效果和数据来源仍需实测，不承诺永久免费、全量数据覆盖或严格准点送达。

## 2. 推荐架构

| 组件 | 建议实现 | 用途与费用边界 |
| --- | --- | --- |
| 网页 | React + TypeScript + Vite，部署为 Cloudflare Workers Static Assets | 手机和电脑共用一个网页；使用免费子域名 |
| 轻量接口 | Cloudflare Worker | 持仓增删改、历史报告读取、定时任务读写入口 |
| 数据库 | Cloudflare D1 | 保存当前持仓、偏好、报告快照和发送记录，保持免费计划 |
| 网页身份验证 | Cloudflare Access，仅允许指定个人身份 | 防止网页和 API 公开暴露持仓；免费计划资格需核对 |
| 每日分析 | 私有 GitHub 仓库的 Actions 标准 Linux runner | 定时执行 Python 采集和分析脚本，使用账号免费分钟 |
| 市场数据 | 免费日线、公开公告与 RSS | 不购买行情或搜索，不依赖试用额度续费 |
| AI | 用户选择的模型 API | 唯一允许付费的外部服务 |
| 发送邮件 | 用户现有 163 邮箱的 SMTP | 发给指定收件人；使用已有免费功能，需验证账号支持 |

```text
手机／电脑浏览器
       │ 登录、编辑持仓、查看报告
       ▼
Cloudflare 网页与 Worker API ─── D1 数据库
       ▲                         │
       │ 受限的机器身份读写         │ 当前持仓及历史报告
       │                         │
GitHub Actions 每日任务 ───────────┘
       ├── 获取免费行情、公告、RSS
       ├── 计算账户指标、整理证据
       ├── 调用 AI API
       ├── 校验并保存日报
       └── 通过现有邮箱 SMTP 发送邮件
```

Cloudflare 的免费 `workers.dev` 子域名可以运行个人项目，无需先购买域名；该地址可配置 Access 登录保护。[workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)、[Access 配置](https://developers.cloudflare.com/workers/configuration/cloudflare-access/)

为什么把分析放在 GitHub Actions：它适合执行 Python 数据处理、较大的文档解析及 SMTP 发送。Cloudflare 免费 Worker 每次调用 CPU 预算较小，保留它承担短小的数据库 API，不把整份研究流程塞入 Worker。[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)

## 3. 免费运行的条件

以下额度依据编写时官方文档，只用于判断单人项目的可行性；开发前重新核对实际账号。

| 项目 | 文档中的免费额度或特性 | 本项目控制方式 |
| --- | --- | --- |
| Workers | 每日 100,000 次请求；每次 10 ms CPU | 仅轻量 API，不做网页全文解析与模型分析 |
| D1 | 每日 500 万行读取、10 万行写入；账户总存储 5 GB | 主键和日期索引、分页；不长期保存全量行情及网页正文 |
| GitHub Free | 私有仓库每月 2,000 标准 runner 分钟 | 每日一次主任务，固定超时，监控整个账号的共用额度 |
| 网页地址 | 平台免费子域名 | 首版不购买域名 |
| 邮件 | 现有邮箱的 SMTP 能力 | 不预设所有邮箱都支持；先验证 TLS、授权方式及云端发送限制 |

参考：[Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)、[D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[GitHub Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。

工作流初始安排在 08:15 启动，报告就绪后等待到 08:30 发送；等待时间也计入 runner 分钟。假设每天总占用 20 分钟，一个 31 天月份约 620 分钟；每天达到 35 分钟超时上限则约 1,085 分钟，尚需另计部署、人工重试和其他仓库用量。这是预算估算，不是实际耗时记录。

保持各平台免费计划，配置可用的支出阻止与用量提醒，不自动升级。超额时暂停或失败并显示状态，不能继续运行并产生未经同意的费用。D1 免费日额度用尽时会拒绝查询；不能依赖它无上限运行。[D1 免费额度执行说明](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/)

## 4. 网页功能

### 4.1 我的持仓

- 列表显示证券名称、代码、市场、数量、平均成本、投资期限和更新时间。
- 添加时验证证券身份。同一证券已存在时引导修改，不重复累计。
- 编辑可以修改数量、成本和买入理由；第一版直接维护当前持仓，不模拟交易流水。
- 支持删除与短时撤销，删除不会改变历史日报中的持仓。
- 可用现金单独填写；改仓不自动推算卖出收入或买入支出。
- 无法确定证券代码、市场或资产类型时不进入个股分析。
- 默认先按 A 股股票和境内 ETF 联调；若用户持有港美股，应在首版补齐相关行情、币种与交易日历，不把海外持仓混入人民币计算。

保存成功必须收到云端确认。网络失败时保留未提交表单，不能仅写入浏览器缓存后显示“已同步”。多标签页编辑使用版本号，过期版本提交返回冲突，提示重新加载，避免覆盖刚保存的持仓。

### 4.2 今日日报与历史

展示日报、生成时间、行情日期、新闻窗口、生成时持仓版本、数据缺失项和邮件发送状态。按日期分页查看历史；同一天重算时保留新旧版本。

日报生成后改仓，页面提示“本报告基于修改前持仓，后续报告将使用新持仓”。第一版不因每次编辑自动重算或重新发邮件，避免重复收费和邮件打扰。

首版的手动重跑由项目管理员在 GitHub Actions 执行；网页一键重算可在后续加入，不为本次持仓管理需求额外开放任务触发权限。

### 4.3 设置

包含投资期限、可承受回撤、仓位约束、现金、日报时区和暂停发送开关。用户没有填写的风险偏好保持未知，不采用系统默认数值冒充用户授权。

首版收件地址和 SMTP 参数由部署配置维护，不通过网页随意修改收件人。更改实际收件地址需要显式确认，避免误把个人报告发送给他人。

## 5. 每日定时与时间口径

目标：每天运行，包括周末和节假日，北京时间 08:30 左右发送。A 股休市时生成资讯和下一交易日准备，不伪造当天行情。

正常流程：

1. 08:15 左右，GitHub Actions 定时工作流启动。
2. 用机器身份读取并冻结持仓、偏好和发送配置，建立本日运行记录。
3. 把本次实际开始采集的时间记为 `cutoffAt`，获取该时间之前最近 24 小时消息和各市场最近有效交易数据。
4. 本地计算指标，生成证据包，调用模型，校验输出。
5. 保存完整报告和输入快照。
6. 若尚未到 08:30，等待到目标时间；若已超过目标时间，就绪后发送并标注生成时间。
7. 记录 SMTP 发送结果，网页显示运行与发送状态。

正常情况下，报告新闻截止时间约为 08:15，不能写成完整覆盖到 08:30。若工作流延迟启动，使用实际截止时间计算窗口。邮件头部必须显示真实窗口；不为追求固定时间而假装读取了尚未获取的数据。

GitHub Actions 的定时任务可能排队延迟，严重时任务可能不执行，因此本方案不保证严格的每日准点送达。网页应显示“最近成功日期”和“今日未生成／发送失败”，支持人工重跑；依赖同一调度器的补跑不能作为独立可靠性保证。[GitHub 定时限制](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows)

初始仅每天一次自动任务，设置 `timeout-minutes: 35`；若任务明显迟到，仍生成并发送当日报告，标题标注“延迟”。若跨越到下一个北京时间日期，不把前一天未完成邮件作为当天正常日报发送，转为需要人工处理。

## 6. 数据与 AI 分析

采用免费来源优先，但必须区分实际已取得的证据与未覆盖项。

| 内容 | 来源路线 | 缺失时处理 |
| --- | --- | --- |
| 股价与日线 | TickFlow 免费历史日 K，其他免费源需单独验证 | 标注最近收盘日期；无价格则不计算该持仓市值 |
| 国内外指数 | 免费服务中已验证支持的指数及公开资料 | 按地区显示缺失；ETF 不冒充指数 |
| 公司公告与财务 | 交易所、巨潮、公司公开披露 | 仅能打开网页不等于自动采集成功；缺财务不做强长期判断 |
| 宏观与海外消息 | 官方政策页与 RSS，例如美联储 | 固定来源覆盖，不能声称全网完整检索 |
| 资金流向 | 可核验的免费公开数据 | 不拿成交额冒充净流入，不让模型编造 |
| 未来事件 | 有来源的公告、日历和政策安排 | 区分已确定安排、市场预期及假设 |

参考：[TickFlow 免费服务](https://docs.tickflow.org/zh-Hans/quickstart)、[美联储 RSS](https://www.federalreserve.gov/feeds/feeds.htm)。

每条消息保留来源链接、发布者、发布时间、获取时间及摘要类型。无可信发布时间的内容只能列为背景，不能强行放入过去 24 小时。转载与更正去重，缓存保留原始数据日期。

Python 确定性计算市值、未实现盈亏、仓位和集中度。缺价格、现金、汇率或行业分类时明确缺失，禁止不完整分母下的精确仓位建议。没有交易流水，不计算已实现收益或把账户资金变化冒充投资收益率。

AI 默认一次调用整份报告，输入结构化指标、必要的持仓信息和经过筛选的证据，不发送 SMTP 密钥、个人身份或云平台凭证。输出固定结构，价格和指标从程序计算结果引用。

建议分三个期限：今日、短期 1–4 周、长期 6–24 个月。每条建议包含动作、支持证据、反对证据或不确定性、触发条件、失效条件和复查时间。风险偏好未知时不推定激进仓位；证据不足允许“保持观察／暂不判断”。

默认每次最多 40 条精选证据和一次模型调用，格式修复最多一次。真实调用量记录到运行表；数据不足时不通过增加多轮 AI 辩论来掩盖缺口。普通模型 API 不自动具有实时联网搜索能力。

## 7. 邮件内容与发送

主题示例：`MarketPilotDaily｜YYYY-MM-DD 持仓日报`。降级或延迟时加上相应标签。使用 HTML 邮件和纯文本替代内容，不只发送一个需要登录的链接。

正文顺序：

1. 三条核心变化，说明与持仓的关系。
2. 国内外市场与资金信息摘要。
3. 账户风险与逐只持仓建议。
4. 今日、短期和长期计划。
5. 未来事件、信息不足项、原始来源链接。
6. 新闻窗口、各类行情日期、持仓版本、生成时间，以及登录后查看历史的网页入口。

邮件默认不包含账户绝对金额、原始持仓数量或成本，可显示持仓名称和建议；详细账户信息留在受保护网页。所有生成文字进行 HTML 转义或严格清洗，禁止原样执行模型或网页提供的 HTML。

SMTP 连接使用 163 邮箱规定的 TLS 和客户端授权方式，不购买域名，不把需要域名验证的商业邮件平台作为默认依赖。实际云端登录、授权码、发送频率和垃圾邮件归类须实测，不能把服务支持 SMTP 当作目标账号发送已验证。

163 网页邮箱的设置中有 POP／SMTP／IMAP 协议入口，启用需要的服务后获取客户端授权码；按实际页面要求完成账号验证。授权码用来连接客户端，不把网页登录密码写入代码。[网易开启客户端协议说明](https://help.mail.126.com/faqDetail.do?code=d7a5dc8471cd0c0e8b4b8f4f8e49998b374173cfe9171305fa1ce630d7f67ac2a5feb28b66796d3b)、[新增授权码说明](https://help.mail.126.com/faqDetail.do?code=d7a5dc8471cd0c0e8b4b8f4f8e49998b374173cfe9171305fa1ce630d7f67ac286624f309a1a7089)

部署配置：

| 配置项 | 计划值／来源 | 保存位置 |
| --- | --- | --- |
| `SMTP_HOST` | 联调候选 `smtp.163.com`，按账号当前设置核对 | 工作流非敏感配置 |
| `SMTP_PORT` | 联调候选 `465`，隐式 TLS | 工作流非敏感配置 |
| `SMTP_USERNAME` | 用户确认的完整 163 发件地址 | GitHub Secrets |
| `SMTP_AUTH_CODE` | 该邮箱的客户端授权码 | GitHub Secrets |
| `MAIL_FROM` | 与被授权的发件账号一致 | GitHub Secrets |
| `MAIL_TO` | 用户确认的唯一收件地址，可以与发件地址相同 | GitHub Secrets |

主机与端口需要在 M0 按网易当前服务器参数和实际 TLS 连接验证。使用标准证书与主机名校验，不因第三方教程而关闭校验；本次没有使用任何凭证做连接或发送测试。[网易服务器参数入口](https://help.mail.126.com/faqDetail.do?code=d7a5dc8471cd0c0e8b4b8f4f8e49998b374173cfe9171305fa1ce630d7f67ac22b85ac2e7c90cd63)

首次部署的测试邮件应发到用户确认的地址。本轮只确定邮件渠道，尚未实际发送任何邮件。

### 7.1 防重复与故障处理

- 每个报告日期只允许一个默认日报运行槽位，数据库唯一约束与 Actions `concurrency` 配合，避免并行自动生成。
- 手动重跑先读取已有报告与发送状态。已有有效报告时，发送重试复用报告，不重新调用 AI。
- 报告生成与邮件发送分开记录；报告保存失败时不能写“发送成功”。
- 发送前持久化 `attemptID` 和 `sending` 状态；SMTP 明确失败可以有限重试。
- SMTP 接受后客户端超时，或接受后状态写回失败，记为 `delivery_uncertain`，不自动再发，交由用户检查邮箱后决定重发。
- 同一 `Message-ID` 有助追踪，但不保证收件服务器自动去重。首版不承诺跨系统严格恰好发送一次。
- 网页状态使用“SMTP 已接受”而不是“已读”或“已成功进入收件箱”；是否被退信或进垃圾箱不能凭 SMTP 返回值确定。

## 8. 云端数据模型和接口

### 8.1 最小数据表

| 表 | 主要字段 | 关键约束 |
| --- | --- | --- |
| `positions` | id、market、exchange、code、asset_type、name、currency、quantity、average_cost、horizon、thesis、updated_at | 证券身份唯一，数量为正，成本可未知 |
| `portfolio_state` | id、revision、cash_json、cash_as_of、updated_at | 编辑持仓和现金时事务性递增 revision |
| `investor_profile` | id、revision、horizon、risk_limits_json、updated_at | 未填写值保持 null |
| `daily_runs` | id、report_date、state、started_at、cutoff_at、portfolio_revision、lease_until、failure_code | 每日期默认运行槽位唯一；中断后按租约和阶段人工恢复 |
| `reports` | id、report_date、version、run_id、input_snapshot_json、result_json、created_at | 保存不可变持仓、资料与模型版本；不会随改仓变化 |
| `deliveries` | id、report_id、attempt_id、state、message_id、accepted_at、last_error | 明确失败与结果未知分开 |

金额和数量保存为十进制字符串，在 Python 或经验证的十进制实现中计算；不能用二进制浮点误差改变持仓成本。报告中保留实际入模证据摘要，缓存删除不破坏历史解释。

### 8.2 页面与任务 API

| 接口 | 调用者 | 行为 |
| --- | --- | --- |
| `GET /api/portfolio` | 本人 | 读取持仓、现金和 revision |
| `POST /api/positions` | 本人 | 新增已验证证券 |
| `PATCH /api/positions/:id` | 本人 | 携带期望 revision 修改；冲突返回 409 |
| `DELETE /api/positions/:id` | 本人 | 删除当前持仓，不删历史快照 |
| `PATCH /api/profile` | 本人 | 更新个人偏好 |
| `GET /api/reports` | 本人 | 按日期分页 |
| `GET /api/reports/:id` | 本人 | 读取报告及生成时依据 |
| `POST /internal/runs/claim` | 定时任务 | 事务性领取当日任务并返回不可变输入快照 |
| `POST /internal/runs/:id/report` | 定时任务 | 幂等写入已校验报告 |
| `POST /internal/runs/:id/delivery` | 定时任务 | 写发送尝试及结果 |

对现金、持仓和 profile 的读取必须形成一致快照，不能在几次请求之间拼出不同版本。领取任务时在数据库批处理中读取和落下快照，核对 revision；任务之后不再使用可变的当前持仓。

## 9. 访问控制与凭证

- 网页和 API 均受 Access 保护，允许名单精确到个人身份；不能配置成允许整个公共邮箱域名访问。
- 使用 Access 已验证身份或正确验证的 JWT，不能直接信任客户端自填的邮箱头。
- GitHub Actions 使用单独的机器身份。Worker 内进一步区分本人和任务身份：机器身份只能访问必要的任务接口，不能通过普通页面接口编辑持仓。
- 保护生产、预览和任何替代入口，避免预览域名绕过登录；上线前逐个测试匿名访问。
- 网页写操作校验 Origin、内容类型和会话，并使用参数化 SQL、服务端字段验证与版本检查。
- AI Key、SMTP 授权信息、机器访问凭证存 GitHub Actions Secrets。部署凭证按需授予最小权限，不放进浏览器 JavaScript 或数据库。
- 真实持仓、报告、邮件地址和原始网页内容不提交到 Git，不作为公开 artifact；日志不打印完整输入或鉴权内容。
- 持仓现在会保存到 Cloudflare，任务会在 GitHub 处理必要数据，邮件由所选邮箱服务处理，模型会收到最小化的分析信息。这些远程处理是自动邮件方案的一部分。

Cloudflare Access 的免费方案和机器身份支持需在实际账号中确认；配置无法满足预算时暂停部署或重新选择免费鉴权方案，不能把私人持仓网页临时改成公开。[Access 配置](https://developers.cloudflare.com/workers/configuration/cloudflare-access/)、[Zero Trust 方案](https://www.cloudflare.com/plans/zero-trust-services/)

## 11. 核心验收

1. 在手机网页添加持仓，电脑网页读取到同样数据；保存失败不显示同步成功。
2. 同名或相似代码的不同市场证券不串数据；空成本与零成本分开。
3. 修改／删除持仓影响下一份日报，不改写已保存历史报告。
4. 同时编辑产生冲突提示，任务读取到单一版本的持仓与偏好。
5. 用户手机和电脑都关闭时，云端任务仍可运行。
6. 邮件包含可直接阅读的内容，来源、时间和条件齐全；网页无需公开才能看邮件。
7. 盘前、休市、跨时区以及延迟行情的日期标签正确。
8. 资金、财务或海外行情缺失时不编造，完整需求缺口记录在交付清单。
9. 正常运行以 08:30 为目标；晚启动、超时或未运行状态可见，不宣称保证准点。
10. 重跑已发日报不会再次生成或发送；明确重发产生独立尝试记录。
11. SMTP 响应不明不会无限自动重发；服务器接受与用户实际收到的状态分开。
12. 匿名访客、伪造身份、预览域名和机器越权访问均被阻止。
13. 免费用量逼近或达到上限时停止对应服务，不自动切换付费计划。
14. 本地自动测试不用真实邮箱或付费模型；真实发送只在用户确认的目标地址进行。
